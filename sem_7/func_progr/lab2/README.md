# Лабораторна робота №2 — варіант 5

Багатопотоковий застосунок на Haskell (GHC з ключем `-threaded`) для розв'язання задачі
**дискретного логарифмування**: знайти найменше `x`, для якого `g^x ≡ h (mod p)`.

## Алгоритми

**1. Повний перебір.** Послідовна версія перевіряє `g^0, g^1, g^2, …`, щоразу множачи на `g`.

Паралельна версія ділить показники між `k` потоками з чергуванням: потік `t` перевіряє
`t, t + k, t + 2k, …`. Він стартує з `g^t` і щоразу множить на `g^k`. Тому кожен потік доходить до
відповіді `x` приблизно за `x / k` кроків, незалежно від того, де лежить `x`. Потоки мають спільну
змінну `IORef` з найменшим знайденим `x`. Кожні 65 536 кроків потік перевіряє, чи не знайдено вже
меншу відповідь, і якщо так — завершується. Потоки запускаються через `forkOn` (по одному на ядро),
результати збираються через `MVar`.

**2. Великий/малий крок (Шенкс).** Нехай `m = ⌈√(p−1)⌉`.
- Малі кроки: таблиця `g^j → j` для `j < m`. Паралельно: кожен потік будує свою частину таблиці,
  потім частини об'єднуються.
- Великі кроки: `h · (g^−m)^i` для `i ≤ m` шукаються в таблиці, відповідь `x = i·m + j`.
  Паралельно: діапазон `i` ділиться між потоками.

Складність — `O(√p)` замість `O(p)`.

Усі обчислення ведуться в `Int`, тому `p ≤ 3 037 000 499`: так добуток двох залишків поміщається
в 64 біти. Обернений елемент `g^−1` знаходиться розширеним алгоритмом Евкліда.

## Запуск

```
cabal run discrete-log
```

Програма запитує `p`, `g`, `h` (Enter — приклад `p = 2^31 − 1`, `g = 7`, `x = 987654321`) і
максимальну кількість потоків. Значення можна передати й аргументами:

```
cabal run discrete-log -- 1000003 2 123456
```

Без cabal:

```
ghc -O2 -threaded -rtsopts "-with-rtsopts=-N" -iapp -isrc app/Main.hs -o discrete-log
./discrete-log
```

Програма вимірює час (`GHC.Clock.getMonotonicTime`) для 1, 2, 4, … потоків, змінюючи кількість
робочих потоків RTS через `setNumCapabilities`. Кожну відповідь вона перевіряє обчисленням `g^x mod p`.

## Результати

Двоядерна машина, `p = 2147483647`, `g = 7`, `h = 7^987654321 mod p`:

```
Метод                        Потоків       Час, с   Прискор.              x  Перевірка
--------------------------------------------------------------------------------------
Повний перебір (послідовно)        1       8.2019       1.00      987654321        так
Повний перебір (паралельно)        1       8.1918       1.00      987654321        так
Повний перебір (паралельно)        2       4.0819       2.01      987654321        так
Великий/малий крок (посл.)         1       0.0320       1.00      987654321        так
Великий/малий крок (пар.)          1       0.0424       0.76      987654321        так
Великий/малий крок (пар.)          2       0.0238       1.34      987654321        так
```

- Повний перебір прискорюється майже лінійно: 2 потоки — у 2.01 раза.
- Метод великого/малого кроку в сотні разів швидший за перебір навіть в одному потоці. На такому `p`
  він працює кілька мілісекунд, тому накладні витрати на створення потоків і об'єднання таблиць
  помітні. Виграш від паралелізму тут невеликий (1.34 раза на 2 потоках) і зростає зі збільшенням `p`.
- На машині з більшою кількістю ядер (наприклад, 8–10) прискорення перебору відповідно більше.
